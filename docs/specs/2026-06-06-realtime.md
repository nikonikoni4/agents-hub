## Overview

**业务问题**：群聊场景下，多个客户端需要实时感知群聊状态变化（如新消息、Agent 状态变更），但缺乏进程级的实时信号分发机制。

**核心职责**：提供进程级 WebSocket 连接管理能力，以房间（room）为单位对连接进行分组，支持向指定群聊房间广播实时刷新信号。

## Scope

### 范围内

- WebSocketManager：管理连接的加入、移除和按房间广播
- 房间模型：按 `group_chat_id` 隔离连接，自动清理空房间
- 依赖注入：进程级单例 + FastAPI `Depends` 注入
- 事件模型：RefreshSignal 数据结构
- 异常体系：WebSocket 相关异常的继承层次

### 范围外

- WebSocket 端点的路由和生命周期管理 → `websocket-backend` spec
- 群聊业务逻辑 → `core-agent-orchestration` spec
- 前端 WebSocket 客户端实现 → `frontend-core` spec
- 消息持久化 → `message-flow-and-persistence` spec

**对外接口**：

| 方法 | 语义 | 约束 |
|------|------|------|
| `connect(websocket, group_chat_id)` | 接受 WebSocket 连接并加入指定房间 | 房间不存在时自动创建 |
| `disconnect(websocket, group_chat_id)` | 从房间移除连接 | 空房间自动销毁；不存在的房间/连接静默忽略 |
| `broadcast(group_chat_id, message)` | 向房间内所有连接广播 JSON 消息 | 空房间记录 DEBUG 日志并跳过；失败连接自动清理 |

**房间模型**：
- 以 `group_chat_id` 为键，值为该房间内的 WebSocket 连接列表
- 一个房间可以有零到多个连接
- 房间在首个连接加入时创建，在最后一个连接离开时自动销毁

### 异常体系

异常采用双重继承设计，同时继承 WebSocket 基类和对应的通用异常基类：

```
AgentsHubError
├── WebSocketError                          # WebSocket 异常基类
│   ├── WebSocketConnectionError            # 连接错误（+ ExternalServiceError）
│   ├── WebSocketRoomNotFoundError          # 房间不存在（+ ResourceNotFoundError）
│   ├── WebSocketBroadcastError             # 广播错误（+ ExternalServiceError）
│   └── WebSocketValidationError            # 校验错误（+ ValidationError）
```

上层可按通用异常类型或 WebSocket 异常类型统一捕获。

## Design Rationale

**为什么以房间为单位管理连接？**
- 群聊场景天然需要按 group_chat_id 隔离连接，房间模型直接映射业务概念
- 避免广播时遍历所有连接，按房间索引可快速定位目标连接

**为什么采用进程级单例 + 惰性初始化？**
- WebSocketManager 管理进程内所有连接状态，必须是单例
- 惰性初始化避免模块导入时的副作用，兼容测试环境的 reset 机制

**为什么异常采用双重继承？**
- 业务层可按 `WebSocketError` 统一捕获所有 WebSocket 相关异常
- 也可按通用异常类型（如 `ResourceNotFoundError`）跨模块统一处理
- 代价是异常类层次略复杂，但收益大于成本

**有哪些约束？**
- 进程级单例，不支持多进程/多实例场景（需外部 Redis 等方案）
- 广播是逐连接串行发送，高并发场景可能需要优化

**有哪些已知限制？**
- 不支持消息确认机制（fire-and-forget）
- 不支持连接认证和权限控制（由上层 WebSocket 端点负责）

**哪些场景会触发广播？**
- 新消息保存到群聊历史时（`GroupChatRuntime.add_message()`）
- 置顶/取消置顶消息时（`GroupChatService.pin_message()`/`unpin_message()`）
- 权限请求状态更新时（`GroupChatService.update_permission_status()`）
- Loop 状态变化时（`LoopExecutor._cleanup()`、`_emergency_stop()`、`_handle_node_completion()`）
