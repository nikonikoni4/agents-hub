## 三、潜在实现问题（需要设计决策）

### 8. 🔴 stop_loop 竞态条件 - 需要新增终止信号机制

**问题**：stop_member 停止 CLI 后，LoopExecutor 会永远阻塞在 `await completion_queue.get()`

**解决方案**：新增终止信号
```python
# stop_loop 流程修改：
1. 向 completion_queue 发送终止信号：
   await completion_queue.put({
       "loop_id": loop_id,
       "node_agent": None,
       "is_termination_signal": True
   })
2. 停止 Agent CLI（stop_member）
3. 重启 Agent CLI（start_member）
4. 设置 Loop 状态为 PAUSED

# LoopExecutor 接收处理：
notification = await self.completion_queue.get()
if notification.get("is_termination_signal"):
    logger.info("收到终止信号，退出循环")
    break
```

**修正点**：
- Slice 7 stop_loop 流程补充步骤 0："发送终止信号到 completion_queue"
- Slice 6 _handle_node_completion() 或 run() 补充：检查 is_termination_signal 并退出

### 9. 🔴 循环重试的消息可见性 - 需要用户决策

**问题**：`_execute_node_with_retry` 每次重试都创建新 AgentCall 并发送消息
- 用户会在群聊历史看到多条重试消息（格式错误的输出）
- 难以追踪哪条是最终结果

**方案 A（推荐）**：重试消息不保存到群聊历史
- 修改：Slice 4 的重试逻辑，创建 AgentCall 时标记 `is_retry=True`
- 修改：Slice 6 的 `_send_to_node()` 方法，重试消息不调用 `runtime.add_message()`
- 优点：群聊历史干净，只保留最终结果
- 缺点：失去重试过程的调试信息

**方案 B**：重试消息标记但保存
- 修改：循环消息格式增加重试标记 `[循环-节点{agent}-第{iteration}轮-重试{retry_count}]`
- 优点：完整的执行记录
- 缺点：群聊历史混乱

**需要用户决策**：选择方案 A 还是 B？

### 10. 🟡 IN_LOOP 状态切换的消息队列残留 - 记录为已知限制

**问题**：切换到 IN_LOOP 时，message_queue 中已有的消息会被拒绝并丢弃

**决策**：记录为 MVP 限制，不修改
- **理由**：
  1. 正常流程下，Agent idle 时队列应该是空的
  2. 如果队列有残留，说明有未完成的任务，此时不应该启动 Loop
  3. 清空队列或通知发送方会增加复杂度

**修正点**：
- `docs/known-contracts/loop-mvp-limitations.md` 补充条目：
  - 标题："状态切换时不处理队列残留消息"
  - 内容："切换到 IN_LOOP 状态时，Agent message_queue 中的待处理消息会被丢弃"
  - 理由："MVP 假设 Agent 在 idle 状态下队列为空"
  - 影响："如果 Agent 有未完成的任务，启动 Loop 会导致消息丢失"
  - 未来扩展："start_loop 前检查队列是否为空，非空时拒绝启动"

### 11. 🟡 loop_context 大小问题 - 记录为已知限制

**问题**：loop_context 包含完整的节点职责和上一节点输出，可能非常大

**决策**：记录为 MVP 限制，不修改
- **理由**：
  1. MVP 阶段先验证功能可行性
  2. 如果实际使用中发现问题，再优化（截断输出、引用机制）

**修正点**：

  - 理由："MVP 阶段先验证功能可行性"
  - 影响："上一节点输出过长时，可能导致内存或序列化问题"
  - 未来扩展："输出截断机制（保留前 N 字符）或引用机制（只传递输出 ID）"

### 12. 🟡 TERMINATOR 解析健壮性 - 在 Slice 4 补充处理

**问题**：XML 解析可能失败（大小写、空格、嵌套在代码块）

**解决方案**：增强解析逻辑
```python
def _validate_terminator_output(self, output: str, node: LoopNode) -> bool:
    # 1. 提取 <loop_decision> 块（忽略大小写、空格）
    pattern = r'<loop_decision[^>]*>(.*?)</loop_decision>'
    match = re.search(pattern, output, re.DOTALL | re.IGNORECASE)
    if not match:
        return False
    
    decision_block = match.group(1)
    
    # 2. 提取 <should_continue> 值（忽略空格、大小写）
    continue_pattern = r'<should_continue[^>]*>(.*?)</should_continue>'
    continue_match = re.search(continue_pattern, decision_block, re.DOTALL | re.IGNORECASE)
    if not continue_match:
        return False
    
    value = continue_match.group(1).strip().lower()
    return value in ("true", "false")
```

**修正点**：
- Slice 4 Notes 补充：TERMINATOR 解析使用正则表达式，忽略大小写和空格
