# 大参数工具调用导致模型"卡住"或"空洞承诺"

## 元信息

- **日期**：2026-06-16
- **影响范围**：Claude Code TUI、agents hub（任何需要生成大文件的场景）
- **严重程度**：中高（用户体验差，任务失败）
- **根因**：模型在工具调用参数接近上限时的保守行为 + 缺少明确的"分块"提示

## 问题描述

### 现象

当任务需要生成大文件（如 900-1000 行的审查报告）时，出现两种失败模式：

**模式1：空洞承诺**（agents hub 中更常见）
```
用户："生成审查报告"
AI："好的，正在将所有审查结果汇总写入报告文件。"
实际行为：没有调用 Write 工具，直接 end_turn
```

**模式2：卡住无响应**（TUI resume 后更常见）
```
用户："使用 Write 工具创建文件..."
AI：输出 thinking，然后卡住 4+ 分钟无响应
JSONL 记录：{"usage": {"output_tokens": 0}} ← 异常
```

### 实验验证

| 指令 | 预期行数 | 结果 | 耗时 |
|------|---------|------|------|
| "写入你好" | 1 行 | ✅ 成功 | 15s |
| "生成审查报告" | ~900 行 | ❌ 卡住 | 6s 后停止 |
| "分段写入 50 行" | 50 行 | ❌ 空洞承诺 | 17s 后停止 |
| "写入 10 行" | 10 行 | ✅ 成功 | - |

## 根因分析

### 1. 工具调用参数的隐式限制

Claude Code system prompt 中提到：
```
⚠️ HARD LIMIT: The transport layer truncates tool output at ~8192 tokens
```

虽然这是指**工具输出**的限制，但**工具输入参数**可能也有类似约束。

**推测的阈值**：
- 单次工具调用参数 > 2000-3000 tokens 时，模型开始"犹豫"
- 900 行 markdown ≈ 3000-4000 tokens → 超过舒适区

### 2. 模型的"自我审查"行为

当准备生成大参数工具调用时，模型可能：
1. 评估参数大小
2. 判断可能超时/被截断
3. **放弃生成工具调用**，转而输出确认性文本
4. 用户看到"我正在做X"，但实际什么都没做

### 3. 为什么 agents hub 频率更高？

agents hub 的典型任务：
- ✅ 收集多个 subagent 的结果
- ✅ 汇总成单个报告文件
- ❌ 报告通常很长（数百行）
- ❌ 更容易触碰参数限制

TUI 直接使用时：
- 用户通常会自然地分步骤
- 较少一次性生成超大文件

### 4. 与之前网络请求 badcase 的相似性

参考：[CLI 断开导致前端卡住](./2026-06-15-cli-disconnect-frontend-stuck.md)

**共同点**：
- 都是**外部约束**（网络超时 / 参数限制）触发
- 都导致**用户侧无明确反馈**（卡住 / 空洞承诺）
- 都**不是 agents hub 代码的 bug**，而是环境/模型的边界条件

**差异**：
- 网络问题：外部不可控（API 限流）
- 参数问题：可通过提示词引导规避

## 解决方案

### 立即可用的 workaround

**在任务指令中明确要求分块**：

```python
# agents hub manager 派发任务时
prompt = f"""
{original_task}

【重要】如果需要生成超过 50 行的文件：
1. 首次用 Write 工具写入前 50 行
2. 后续用 Edit 工具每次追加 50 行
3. 禁止一次性生成超过 100 行的内容
"""
```

### 根本性改进（需要模型/API 层支持）

1. **明确的参数限制提示**：
   - 如果工具调用参数超过 N tokens，API 返回明确错误而非挂起

2. **分块工具的原生支持**：
   - `WriteChunked(file_path, chunk_size=50)` 
   - 模型自动分批调用

3. **agents hub 层的拦截**：
   - 检测到"生成大文件"任务时，自动注入分块指令

## 识别规则

### 什么时候怀疑是这个问题？

**症状检查清单**：
- ✅ 任务涉及生成长文件（> 100 行）
- ✅ 模型输出"好的，开始写入..."但无工具调用
- ✅ 或者输出 thinking 后卡住
- ✅ JSONL 中 `"output_tokens": 0` 或缺少 `stop_reason`
- ✅ 改成小文件（< 20 行）就成功

### 排查步骤

1. 检查 JSONL 最后一条消息：
   ```bash
   tail -n 1 session.jsonl | jq '.message.content'
   ```
   - 只有 thinking？→ 可能卡住
   - 只有 text 无 tool_use？→ 空洞承诺

2. 估算目标文件大小：
   - < 50 行：不太可能是这个问题
   - 50-200 行：可能触发
   - > 200 行：高概率触发

3. 测试小文件：
   ```
   用户："先只写入前 10 行"
   ```
   - 成功 → 确认是参数限制问题
   - 失败 → 可能是其他问题
