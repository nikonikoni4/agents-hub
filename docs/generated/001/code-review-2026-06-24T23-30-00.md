## 变更摘要

本次合并提交实现了 **群聊 Agent 流式首响功能**（task-38-agent-bridge-stream），支持 Agent 在执行过程中提前返回首句响应，改善用户体验。

### 核心变更

**1. 新增数据模型**
- `FirstResponseResult` 数据类（`models.py:69-73`）：包装首句文本和完整结果

**2. AgentBridge 层**（`bridge.py:378-467`）
- 新增 `execute_with_first_response()` 方法
- 流式遍历事件，检测 `FIRST_RESPONSE` 事件标记
- 分离首句和剩余内容的收集
- Codex 首次调用回退到 `execute()`（不支持流式）

**3. Agent 执行层**（`base_agent.py:206-286`）
- 新增 `execute_with_first_response()` 方法
- Docker 模式回退到 `execute()`（不支持流式）
- 首句完成时立即调用 `runtime.add_message()` 写入群聊历史
- 返回完整结果（首句 + 剩余内容）

**4. 平台适配器**（`parsers/`）
- **Claude 解析器**：检测 `content_block_stop` 事件，且之前有 `TEXT_DELTA`，则发送 `FIRST_RESPONSE` 事件
- **Codex 解析器**：检测 `item.completed` 事件，且 `item.type == agent_message`，则发送 `FIRST_RESPONSE` 事件

**5. 测试覆盖**（442 行）
- `FirstResponseResult` 数据类测试
- 正常流程（首句检测 + 完整结果）
- Codex 首次调用回退
- Docker 模式回退
- 执行失败场景
- 并发场景

### 架构变更

```
原流程：execute() → 返回完整结果
新流程：execute_with_first_response() → 返回首句 + 继续收集 → 返回完整结果
        ↓ 首句完成时
        立即 add_message() 写入群聊历史 + 前端刷新
```

**关键约束**：
- Docker 模式和 Codex 首次调用不支持流式，自动回退
- 纯工具调用（无文本）时不发送首次响应
- 首句检测条件因平台而异（Claude vs Codex）

## 其他观察（置信度 < 80）

以下问题虽然未达到阻塞级别，但值得关注：

### 性能优化建议
- **Codex Parser 缓存无界**（置信度 75）: `_pending_events` 列表无大小限制，异常流可能导致内存累积。建议添加 `maxlen` 或显式清理逻辑。

### 架构设计讨论
- **回退策略分层不一致**（置信度 60）: Codex 回退在 Bridge 层，Docker 回退在 Agent 层。建议统一到单一层级或文档说明设计原因。
- **Parser 状态管理**（置信度 50）: Parser 引入有状态首响检测（`_has_text_delta`, `_pending_events`），虽然通过"每次创建新实例"避免了并发问题，但增加了实现复杂度。

### 测试覆盖建议
- Parser 层的状态机行为（`_has_text_delta` 标记、`_pending_events` 队列）缺少独立单元测试
- Agent 层的 Docker 回退和首句写入 Runtime 缺少端到端集成测试
- `_extract_usage()` 方法缺少单元测试

### 代码质量改进

- `_extract_usage()` 和 `FirstResponseResult` 缺少完整的 docstring
