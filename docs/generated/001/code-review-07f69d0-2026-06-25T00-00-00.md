### Issue 1: 违反 DRY 原则 - 硬编码路径重复

- **类型**: Code Quality
- **置信度**: 85
- **位置**: 
  - `agents_hub/scheduler/task/memory_task.py:95`
  - `agents_hub/mcp/server.py:1525`
- **详情**: 
  两处都硬编码了 `config.memory_path / "agents_hub_history" / "history.jsonl"` 路径，违反 DRY（Don't Repeat Yourself）原则。如果路径结构需要调整，必须修改两处代码，容易遗漏导致不一致。
  
  ```python
  # memory_task.py:95
  history_file = config.memory_path / "agents_hub_history" / "history.jsonl"
  
  # server.py:1525
  history_file = config.memory_path / "agents_hub_history" / "history.jsonl"
  ```
  
- **依据**: CLAUDE.md 核心编码原则第 2 条 DRY
- **建议修复**:
  在 `agents_hub/config/config.py` 中添加属性：
  ```python
  @property
  def history_jsonl_path(self) -> Path:
      """历史总结文件路径"""
      return self.memory_path / "agents_hub_history" / "history.jsonl"
  ```
  然后在两处调用改为 `config.history_jsonl_path`

### Issue 2: APScheduler 补偿任务未在关闭时取消，存在任务泄漏风险

- **类型**: Performance / Resource Management
- **置信度**: 80
- **位置**: `agents_hub/scheduler/scheduler_service.py:84` 和 `96-104`
- **详情**: 
  补偿执行逻辑创建了异步任务 `self._compensation_task = asyncio.create_task(...)`（第 84 行），但在 `shutdown()` 方法（96-104 行）中未取消该任务。
  
  如果服务关闭时补偿任务仍在执行中（例如正在遍历 10 个群聊），该任务会继续占用资源，导致：
  1. 任务泄漏（后台继续执行）
  2. 资源未释放（网络连接、文件句柄）
  3. FastAPI 关闭时可能产生警告日志
  
  ```python
  # scheduler_service.py:84 - 创建任务
  self._compensation_task = asyncio.create_task(self._check_compensation())
  
  # scheduler_service.py:96-104 - shutdown() 未取消任务
  async def shutdown(self) -> None:
      """关闭调度器"""
      if self._scheduler and self._scheduler.running:
          self._scheduler.shutdown()
          self.logger.info("调度器已关闭")
      # ❌ 缺少：self._compensation_task.cancel()
  ```
  
- **依据**: 
  - Python asyncio 最佳实践：创建的任务应在适当时机取消
  - `docs/coding-rules/backend-concurrency.md` 资源管理规范
  
- **建议修复**:
  在 `shutdown()` 方法中添加任务取消逻辑：
  ```python
  async def shutdown(self) -> None:
      """关闭调度器"""
      # 取消补偿任务
      if self._compensation_task and not self._compensation_task.done():
          self._compensation_task.cancel()
          try:
              await self._compensation_task
          except asyncio.CancelledError:
              pass
      
      if self._scheduler and self._scheduler.running:
          self._scheduler.shutdown()
          self.logger.info("调度器已关闭")
  ```

## 变更摘要

本次合并提交实现了**定时记忆助手调度系统**，支持每天在配置时间自动收集所有活跃群聊的消息并更新记忆文件。

### 核心功能

**1. 调度服务**（`agents_hub/scheduler/scheduler_service.py`, 183 行）
- 基于 APScheduler 的异步调度框架
- 定时触发记忆收集任务（默认每天 10:00）
- 启动时自动补偿执行（检查今天是否已执行）
- 幂等启停设计

**2. 状态管理**（`agents_hub/scheduler/state_manager.py`, 109 行）
- 管理 3 个 JSON 状态文件：
  - `.schedule_state.json` - 执行状态（日期戳）
  - `index.json` - 群聊索引
  - `result.json` - 执行结果（保留最近 10 条）
- 提供日期比较、状态读写、结果追加功能

**3. 记忆任务**（`agents_hub/scheduler/task/memory_task.py`, 102 行）
- 调用 Memory Assistant Agent 执行单个群聊的记忆收集
- 执行后自动裁剪 `history.jsonl` 至最近 1000 条
- 异常捕获返回错误描述（不抛出）

**4. MCP 工具扩展**（`agents_hub/mcp/server.py`, +118 行）
- 新增 `get_memory_context()` 工具（第 15 个 MCP 工具）
- 提供群聊上下文：历史总结 + 新消息
- 三重权限验证：Token 验证 + 群聊归属校验 + 角色校验

**5. 会话解析工具**（`agents_hub/utils/session_parser.py`, 102 行）
- 统一支持 Claude Code 和 Codex 平台的 session 文件解析
- `get_group_chat_messages()` 从群聊 JSONL 按时间段截取消息

**6. 配置扩展**（`agents_hub/config/config.py`, +51 行）
- 新增 4 项配置：`default_assistant_name`、`default_memory_assistant_name`、`memory_path`、`memory_task_cron_*`

**7. Bootstrap 集成**（`agents_hub/bootstrap.py`, +47 行）
- 初始化 Memory Assistant 系统角色
- 配置禁用工具黑名单（只保留数据读写）

**8. FastAPI 集成**（`agents_hub/api/app.py`, +7 行）
- Lifespan 事件中启动/关闭调度器
