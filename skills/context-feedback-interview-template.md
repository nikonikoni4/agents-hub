# Agent 上下文反馈访谈模板

**目标**：从 Agent 实际获取信息的角度，收集上下文提供的有效性和效率问题

**使用场景**：在 Agent 完成任务后，询问其在任务过程中遇到的上下文问题

---

## 访谈提示词

你刚刚完成了 [任务描述]。现在我想从你实际获取信息的角度，了解你在这个过程中遇到的上下文问题。

请回答以下问题：

**问题**：在完成任务的过程中，你花了多少时间在"找信息"（搜索代码、查找定义、追踪调用）上？

- [ ] > 80%（几乎全在找信息）

**补充说明**：具体哪些信息最难找到？

- **你是如何绕过这个问题的**：（如：逐个文件搜索、推测、询问用户等）
- **如果有这个信息，能节省多少时间**：

**问题**：在完成任务时，有哪些信息是你读了但实际上用不到的？

请具体说明：
- **哪些文档/代码段是冗余的**：

### 4. 最有帮助的上下文

**问题**：在完成任务时，哪些信息/文档对你帮助最大？

请具体说明：
- **最有帮助的信息是什么**：

## 使用说明

### 何时使用

- Agent 完成一个非平凡任务后（如：修复 bug、实现新功能、重构代码）
- Agent 明显卡住或花费大量时间搜索信息时
- 定期收集（如：每周选择 1-2 个任务进行访谈）

### 如何使用

1. **任务完成后立即访谈**（记忆最清晰）
2. **提示 Agent 从"实际获取信息"的角度回答**（不是理论上需要什么，而是实际过程中缺什么）
3. **记录具体示例**（不要只说"缺少上下文"，要说缺少什么、在哪里卡住）
4. **定期汇总**（每周/每月汇总访谈记录，识别共性问题）

### 注意事项

1. **不要在任务中途打断访谈**（会干扰 Agent 的工作流程）
2. **不要只访谈失败的任务**（成功的任务也可能有改进空间）
3. **不要只关注"缺失"**（也要关注"冗余"和"最有帮助"）
4. **不要追求完美答案**（快速收集、快速迭代，而不是一次性设计完美方案）

## 示例访谈记录

**任务**：修复 WebSocket 消息丢失问题  
**Agent**：Debug Agent  
**日期**：2026-06-17  
**任务耗时**：2 小时

---

### Agent 反馈

**信息获取效率**：60%（大部分时间在找信息）

**缺失的上下文**：
- WebSocket 重连协议（前端是否发送握手消息？）
- 消息 ID 体系（用 timestamp 还是 message_id？）
- API `/messages` 的参数语义（cursor 是什么？支持 since 吗？）

**如何绕过**：
- 逐个文件搜索 `cursor`、`timestamp`、`message_id`
- 读取前端代码理解重连逻辑
- 推测 API 行为（不确定是否正确）

**节省时间**：如果有 WebSocket 流程图 + API 参数文档，可以节省 1.5 小时

**冗余信息**：
- 读了数据库 schema，但任务不涉及数据库修改
- 读了 Agent 状态机逻辑，但与 WebSocket 无关

**最有帮助的上下文**：
- 前端 `useChatMessages.ts` 的代码（理解了重连逻辑）
- 后端 `get_messages` 的实现（理解了 cursor 参数）

**信息组织问题**：
- API 端点没有文档，只能看代码
- WebSocket 相关逻辑分散在多个文件中，没有索引

**理想形式**：
- WebSocket 流程图（连接、重连、补拉的完整流程）
- API 端点文档（参数、返回值、限制）
- 已知限制章节（消息丢失场景 + 临时方案 + 长期方案）

---

### 关键发现

**最大痛点**：WebSocket 重连协议和 API 参数语义不清晰，花了 1.5 小时搜索和推测

**缺失信息**：
- WebSocket 流程图
- API 参数文档
- 已知限制说明

**冗余信息**：
- 数据库 schema（与任务无关）
- Agent 状态机逻辑（与任务无关）

**最有价值的上下文**：
- 前端重连逻辑代码
- 后端 API 实现代码
