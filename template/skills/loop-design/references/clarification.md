# 需求澄清清单

## 使用说明

在设计循环之前，逐个询问用户以下问题，确保需求理解对齐。

## 澄清问题

### 问题 1：问题定义

**询问**：这个循环要解决什么问题？

**追问要点**：
- 具体是什么类型的任务？（代码开发、文档撰写、数据处理等）
- 任务的复杂度如何？
- 为什么需要循环而不是单次执行？

**示例回答**：
- "我需要实现一个用户登录功能，并通过代码审查确保质量"
- "我需要撰写一份技术文档，并通过编辑确保质量"

---

### 问题 2：参与角色

**询问**：需要哪些 Agent 参与？每个 Agent 的核心职责是什么？

**追问要点**：
- 每个 Agent 的主要职责是什么？
- Agent 之间如何分工？
- 是否有现成的 Agent 可以使用？

**示例回答**：
- "executor 负责代码实现，reviewer 负责代码审查"
- "writer 负责文档撰写，editor 负责文档编辑"

---

### 问题 3：退出条件

**询问**：循环的退出条件是什么？由谁来判断？

**追问要点**：
- 什么时候循环应该结束？
- 由哪个节点来判断？
- 判断标准是什么？

**示例回答**：
- "当 reviewer 认为代码质量达标时退出"
- "当 editor 认为文档质量达标时退出"

---

### 问题 4：循环轮数

**询问**：预期的循环轮数大概是多少？

**追问要点**：
- 任务的复杂度如何？
- 历史经验中通常需要几轮？
- 设置一个合理的上限

**示例回答**：
- "通常 3-5 轮可以完成"
- "设置最大 10 轮比较合理"

---

### 问题 5：特殊约束

**询问**：有没有特殊的约束或要求？

**追问要点**：
- 输出格式有特殊要求吗？
- 有时间限制吗？
- 有其他特殊考虑吗？

**示例回答**：
- "代码需要符合 PEP8 规范"
- "文档需要包含代码示例"

---

## 需求总结模板

完成所有澄清后，输出需求总结让用户确认：

```markdown
## 需求总结

- **问题**：{问题描述}
- **参与角色**：
  - {角色1}：{职责}
  - {角色2}：{职责}
- **退出条件**：{退出条件}
- **预期轮数**：{轮数}
- **特殊约束**：{约束}

请确认以上理解是否正确。
```

## 澄清原则

1. **逐个问题询问**：每次只问一个问题，避免信息过载
2. **复述确认**：用户回答后，复述理解并确认
3. **追问细节**：如果回答模糊，追问具体细节
4. **记录要点**：记录关键信息，用于后续设计
5. **总结确认**：所有问题澄清后，输出总结让用户确认

## 常见问题处理

### 用户回答模糊

**情况**：用户说"我需要一个循环来处理代码"

**追问**：
- "具体是什么类型的代码处理？实现、审查、还是重构？"
- "需要哪些角色参与？"
- "退出条件是什么？"

### 用户不确定

**情况**：用户说"我不确定需要几轮"

**建议**：
- "根据经验，类似任务通常需要 3-5 轮。建议设置最大 10 轮作为上限。"

### 需求过于复杂

**情况**：用户描述的需求涉及多个子任务

**建议**：
- "这个需求可能需要拆分成多个循环。我们先聚焦于最核心的部分。"
