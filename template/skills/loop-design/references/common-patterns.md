# 常见循环模式

## 模式 1：Executor-Reviewer（实现-审查）

### 适用场景

- 代码实现与审查
- 文档撰写与审核
- 方案设计与评审

### 节点设计

**Executor 节点 (normal)**:
```
职责定位：
- 在这个循环中我要做什么：根据需求或反馈实现代码
- 核心任务：编写/修改代码

输入分析：
- 我需要接收什么信息：需求描述或审查反馈
- 上游节点会给我什么：审查意见（如果是第二轮及以后）

输出定义：
- 我需要输出什么：实现的代码
- 输出格式：Markdown 格式，包含代码和修改说明
- 必需字段：## 实现代码、## 修改说明
```

**Reviewer 节点 (terminator)**:
```
职责定位：
- 在这个循环中我要做什么：审查代码质量，判断是否通过
- 核心任务：代码审查、质量判断

输入分析：
- 我需要接收什么信息：实现的代码
- 上游节点会给我什么：Executor 的代码输出

输出定义：
- 我需要输出什么：审查意见和结论
- 输出格式：Markdown 格式，包含审查意见和结论
- 必需字段：## 审查意见、## 审查结论
```

### 提示词示例

**Executor role_description**:
```
你是代码实现者（Executor）。
输入：你会收到上一轮审查者的反馈意见。
职责：根据反馈意见修改代码，修复问题。
输出：修改后的代码和修改说明。
```

**Reviewer role_description**:
```
你是代码审查者（Reviewer）。
输入：你会收到 Executor 实现的代码。
职责：审查代码质量，检查是否符合要求。
输出：审查意见，指出问题或确认通过。
```

## 模式 2：Writer-Editor（撰写-编辑）

### 适用场景

- 文档撰写与编辑
- 内容创作与润色
- 翻译与校对

### 节点设计

**Writer 节点 (normal)**:
```
职责定位：
- 在这个循环中我要做什么：根据需求或反馈撰写/修改文档
- 核心任务：内容创作

输入分析：
- 我需要接收什么信息：写作需求或编辑反馈
- 上游节点会给我什么：编辑意见（如果是第二轮及以后）

输出定义：
- 我需要输出什么：撰写/修改后的文档
- 输出格式：Markdown 格式
- 必需字段：## 文档内容、## 修改说明
```

**Editor 节点 (terminator)**:
```
职责定位：
- 在这个循环中我要做什么：编辑文档，判断质量是否达标
- 核心任务：内容审核、质量判断

输入分析：
- 我需要接收什么信息：撰写/修改后的文档
- 上游节点会给我什么：Writer 的文档输出

输出定义：
- 我需要输出什么：编辑意见和结论
- 输出格式：Markdown 格式
- 必需字段：## 编辑意见、## 审核结论
```

## 模式 3：Processor-Validator（处理-校验）

### 适用场景

- 数据处理与校验
- 格式转换与验证
- 计算与结果验证

### 节点设计

**Processor 节点 (normal)**:
```
职责定位：
- 在这个循环中我要做什么：处理数据/执行计算
- 核心任务：数据处理

输入分析：
- 我需要接收什么信息：待处理的数据或任务描述
- 上游节点会给我什么：校验失败的反馈（如果是第二轮及以后）

输出定义：
- 我需要输出什么：处理结果
- 输出格式：结构化数据
- 必需字段：## 处理结果、## 处理说明
```

**Validator 节点 (terminator)**:
```
职责定位：
- 在这个循环中我要做什么：校验处理结果，判断是否符合要求
- 核心任务：结果校验、质量判断

输入分析：
- 我需要接收什么信息：处理结果
- 上游节点会给我什么：Processor 的处理输出

输出定义：
- 我需要输出什么：校验意见和结论
- 输出格式：Markdown 格式
- 必需字段：## 校验意见、## 校验结论
```

## 模式选择指南

| 场景 | 推荐模式 | 说明 |
|------|----------|------|
| 代码开发 | Executor-Reviewer | 实现+审查 |
| 文档撰写 | Writer-Editor | 创作+编辑 |
| 数据处理 | Processor-Validator | 处理+校验 |
| 方案设计 | Executor-Reviewer | 设计+评审 |
| 翻译工作 | Writer-Editor | 翻译+校对 |
