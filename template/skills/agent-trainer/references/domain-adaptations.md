# 领域适配指南

工作流程是领域无关的，但不同领域在元规则和知识重点上有所差异。本文档提供各领域的适配建议。

---

## 编程/开发领域

### 元规则重点

**执行前 Checklist**：
- [ ] 架构理解：当前模块在整体架构中的位置？
- [ ] 依赖确认：需要哪些库/服务？版本要求？
- [ ] 测试策略：如何验证功能正确性？
- [ ] 技术约束：性能要求、兼容性、安全性？

**决策风格**：
- 优先简单方案，避免过度设计
- 技术选型遵循项目现有技术栈
- 不确定时查阅项目文档或询问用户
- 重构需谨慎，确保不破坏现有功能

**执行后自检**：
- [ ] 回归检查：修改是否引入新 bug？
- [ ] 代码可理解性：其他开发者能否快速理解？注释是否充分？
- [ ] 架构合理性：实现位置、职责划分、耦合度是否合理？
- [ ] 测试覆盖：关键路径是否有测试？

### 知识库重点

- **设计模式**：常用模式（工厂、单例、观察者等）和应用场景
- **重构技巧**：如何安全地改进代码结构
- **调试策略**：如何快速定位和解决问题
- **性能优化**：常见性能瓶颈和优化方法
- **安全最佳实践**：常见漏洞和防护措施

### 典型场景

- 需要理解复杂的项目架构
- 需要遵循特定的代码规范
- 需要编写测试和文档
- 需要考虑性能和安全性

## 内容创作（写作、视频、设计）

### 元规则重点

**执行前 Checklist**：
- [ ] 受众理解：目标受众是谁？他们的需求和背景？
- [ ] 目标明确：内容的核心目标是什么？
- [ ] 风格确认：遵循什么风格指南？（正式/轻松、教学/娱乐）
- [ ] 格式约束：长度、格式、平台要求？

**决策风格**：
- 优先清晰易懂，避免过度复杂
- 风格一致性高于个人偏好
- 创意决策时询问用户意见
- 技术问题（排版、格式）必须符合标准

**执行后自检**：
- [ ] 受众适配：内容是否符合目标受众水平？
- [ ] 风格一致：整体风格是否统一？
- [ ] 创意验证：核心创意是否清晰传达？
- [ ] 技术质量：格式、排版、视觉效果是否专业？

### 知识库重点

- **叙事技巧**：如何构建吸引人的故事结构
- **视觉构图**：构图原则、色彩搭配、视觉层次
- **节奏把控**：如何控制内容的节奏和密度
- **受众心理**：如何理解和满足受众期待
- **平台特性**：不同平台的内容特点和优化策略

### 典型场景

- 需要理解目标受众的心理和需求
- 需要在创意和技术规范间平衡
- 需要保持品牌或个人风格一致性
- 需要适配不同平台的内容形式

## 专业服务（法律、金融、咨询）

### 元规则重点

**执行前 Checklist**：
- [ ] 术语精确性：关键术语是否使用准确？
- [ ] 合规确认：是否符合行业法规和标准？
- [ ] 文档完整性：所有必需信息是否齐全？
- [ ] 审核要求：是否需要专家审核？

**决策风格**：
- 保守优先，避免法律或财务风险
- 术语使用必须精确，不能模糊
- 不确定时必须标注并寻求专业意见
- 引用来源必须可追溯

**执行后自检**：
- [ ] 术语准确性：所有专业术语是否正确使用？
- [ ] 合规性：是否符合相关法规和标准？
- [ ] 完整性：是否涵盖所有必要内容？
- [ ] 可审计性：推理过程和依据是否清晰可追溯？

### 知识库重点

- **行业法规**：相关法律法规和合规要求
- **分析框架**：行业标准的分析方法和模型
- **报告模板**：标准的文档格式和结构
- **术语词典**：行业专业术语的精确定义
- **案例参考**：典型案例和处理方式

### 典型场景

- 需要处理高风险的专业文档
- 需要确保法律和财务准确性
- 需要遵循严格的行业标准
- 需要可追溯的推理和依据

## 创意/艺术（视频剪辑、音乐、设计）

### 元规则重点

**执行前 Checklist**：
- [ ] 创意意图理解：创作的核心意图和情感表达？
- [ ] 技术规范确认：格式、分辨率、色彩空间等技术要求？
- [ ] 工具选择：使用什么工具和技术实现？
- [ ] 参考资料：是否有风格参考或灵感来源？

**决策风格**：
- 技术标准必须严格遵守（格式、规格）
- 创意方向倾向询问用户偏好
- 在技术和创意间寻找平衡
- 工具使用遵循项目标准

**执行后自检**：
- [ ] 技术质量：是否符合技术规范（分辨率、格式、色彩）？
- [ ] 创意表达：核心创意是否有效传达？
- [ ] 工具使用：是否充分利用工具特性？
- [ ] 美学水准：整体美学效果是否达标？

### 知识库重点

- **美学原则**：构图、色彩、节奏、对比等基础原则
- **工具指南**：剪辑软件、设计工具的使用技巧
- **技术规范**：格式、分辨率、色彩管理等技术标准
- **风格参考**：不同风格的特征和实现方法
- **常见问题**：新手常犯错误和避免方法

### 典型场景

- 需要在技术规范和创意表达间平衡
- 需要理解和实现特定的美学风格
- 需要熟练使用专业工具
- 需要控制作品的情感和氛围

## 科研/学术

### 元规则重点

**执行前 Checklist**：
- [ ] 研究方法：采用什么研究方法？是否合理？
- [ ] 文献综述：相关文献是否充分调研？
- [ ] 数据来源：数据来源是否可靠？
- [ ] 伦理考量：是否涉及伦理问题？

**决策风格**：
- 严谨优先，避免过度推测
- 主张必须有证据支持
- 不确定时明确标注
- 引用必须准确完整

**执行后自检**：
- [ ] 逻辑严密性：论证是否严密完整？
- [ ] 证据充分性：每个论点是否有足够证据？
- [ ] 引用准确性：所有引用是否准确标注？
- [ ] 可重复性：方法描述是否足够详细？

### 知识库重点

- **研究方法**：常用研究方法和适用场景
- **统计分析**：数据分析方法和工具
- **学术写作**：论文结构和写作规范
- **引用规范**：不同领域的引用格式
- **领域知识**：特定领域的理论和前沿

---

## 教育/培训

### 元规则重点

**执行前 Checklist**：
- [ ] 学习者水平：目标学习者的背景和水平？
- [ ] 学习目标：期望学习者掌握什么？
- [ ] 教学方法：采用什么教学方法？
- [ ] 评估方式：如何验证学习效果？

**决策风格**：
- 从简单到复杂，循序渐进
- 用具体例子辅助抽象概念
- 避免术语堆砌，注重理解
- 鼓励主动思考和实践

**执行后自检**：
- [ ] 难度适配：内容难度是否匹配学习者水平？
- [ ] 清晰度：概念解释是否清晰易懂？
- [ ] 实践性：是否提供足够的练习机会？
- [ ] 反馈机制：是否有评估和反馈环节？

### 知识库重点

- **教学设计**：课程设计原则和方法
- **认知理论**：学习过程和认知规律
- **教学工具**：各种教学工具和技术
- **评估方法**：学习效果评估方式
- **案例库**：教学案例和最佳实践

## 使用建议

### 如何选择适配方案

1. **识别核心领域**：Agent 主要服务于哪个领域？
2. **参考对应章节**：阅读该领域的元规则重点和知识库重点
3. **定制化调整**：根据具体需求调整 Checklist 和知识类别
4. **交叉领域**：如果涉及多个领域，结合多个章节的建议

### 跨领域场景

**示例**：技术写作 Agent（编程 + 内容创作）

**元规则融合**：
- 执行前：架构理解（编程）+ 受众理解（内容创作）
- 决策风格：技术准确性（编程）+ 清晰易懂（内容创作）
- 执行后：代码正确性（编程）+ 受众适配（内容创作）

**知识库融合**：
- 技术内容：设计模式、最佳实践
- 写作技巧：技术文档写作规范、示例设计

---

## 注意事项

1. **不要生搬硬套**：领域适配只是参考，根据实际需求调整
2. **保持简洁**：不要把所有建议都加入，选择最关键的 3-5 项
3. **用户优先**：如果用户有特定要求，优先用户要求
4. **持续迭代**：根据实际使用效果调整元规则和知识库
