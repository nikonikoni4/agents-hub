# 来源质量指南

本文档定义如何评估和使用不同质量等级的信息来源。

## 质量分级

### Tier A：权威来源
**定义**：
- 官方文档
- 行业标准
- 学术研究
- 技术规范
- 一手资料

**示例**：
- React 官方文档
- W3C 标准
- IEEE 论文
- RFC 文档
- Python 官方文档
- YouTube Creator Academy 官方指南

**特征**：
- 由权威机构发布
- 经过同行评审或官方审核
- 定期更新维护
- 有明确的版本和发布日期

---

### Tier B：高质量专业内容
**定义**：
- 高质量专业文章
- 专家分析（带具体案例）
- 知名技术博客
- 有信誉的行业出版物
- 会议演讲（来自认可的专家）

**示例**：
- Martin Fowler 的重构文章
- Google Developers Blog
- Smashing Magazine
- A List Apart
- Netflix Tech Blog
- 知名会议（如 React Conf）的演讲

**特征**：
- 作者有可验证的专业背景
- 包含具体案例和实践经验
- 有技术深度，非表面介绍
- 来源可追溯

---

### Tier C：一般社区内容
**定义**：
- 一般教程
- 社区讨论
- 个人博客（无专业验证）
- 论坛帖子
- 聚合网站

**示例**：
- Medium 文章
- Dev.to 帖子
- Reddit 讨论
- Stack Overflow 回答
- 个人技术博客
- 通用的"如何做 X"教程

**特征**：
- 作者背景不明确
- 可能包含有用信息，但未经验证
- 缺少权威性引用
- 可能过时或不准确

---

### Tier D：低质量内容
**定义**：
- 营销内容
- 点击诱饵
- 无法验证的声明
- 匿名来源
- 内容农场

**示例**：
- SEO 优化的比较文章（"Top 10 XXX"）
- 供应商营销页面（未标明广告）
- 抄袭或转载的内容
- 无作者署名的文章
- AI 生成的批量内容

**特征**：
- 以营销为目的
- 缺少实质内容
- 无法追溯来源
- 充满夸张宣传

---

## 使用规则

### 元规则的来源要求
**规则**：元规则可以从 Tier A/B/C 获得灵感（因为是抽象准则）

**原因**：
- 元规则是通用的思考方式
- 即使来自个人经验（Tier C），也可能有价值
- 重点是逻辑合理性，不是权威性

**示例**：
- Tier C 社区讨论："我发现每次开始编码前先列清单，错误少很多"
- → 可以启发：执行前 Checklist 的设计

---

### 领域知识的来源要求
**规则**：领域知识必须基于 Tier A/B 来源

**原因**：
- 领域知识涉及具体技术细节
- 错误的知识会导致错误的实践
- 需要权威性保证准确性

**示例**：
- ✅ Tier A："React 官方文档推荐使用 Hooks"
- ❌ Tier C："我觉得 Hooks 不好用，还是用 Class"

---

### Tier C 的使用规则
**可以用于**：
- 发现线索和关键词
- 提出待验证的假设
- 识别争议点

**不能用于**：
- 单独作为元规则或知识的依据
- 必须与 Tier A/B 来源结合验证

**示例**：
- Tier C 提到"视频剪辑的 J-cut 技巧"
- → 搜索 Tier A/B 来源验证 J-cut 的定义和使用场景
- → 验证后才能写入知识库

---

### Tier D 的处理
**规则**：完全排除，不作为任何依据

**识别方法**：
- URL 包含明显的 SEO 关键词堆砌
- 标题使用"最好的"、"必备的"等营销词汇
- 内容肤浅，缺乏深度
- 无作者信息或匿名

---

## 验证规则

### 关键声明的验证要求
**规则**：任何关键声明需要以下之一：
1. **两个独立的 Tier A/B 来源**
2. **一个 Tier A + 一个 Tier B 验证**

**关键声明定义**：
- 影响最终推荐的核心论点
- 技术选型建议
- 明确的"应该"或"不应该"

**示例 1**（符合）：
- Tier A（React 官方文档）："推荐使用函数组件和 Hooks"
- Tier B（Kent C. Dodds 博客）："我的团队全面迁移到 Hooks 后，代码更简洁"
- → 可以作为关键声明

**示例 2**（不符合）：
- 仅 Tier C（Reddit 帖子）："我觉得 Hooks 更好"
- → 不能作为关键声明，需要降级为"建议实践（未验证）"

---

### 证据不足时的处理
**规则**：如果证据质量不足，必须降级处理

**降级方式**：
1. 标注为"建议实践（未验证）"
2. 移入"信息缺口"列表
3. 不写入强约束，只作为参考

**示例**：
- 搜索到的调色标准只有 Tier C 来源
- → 不写入知识库作为最佳实践
- → 记录到信息缺口："调色标准（未找到权威来源）"

---

## 冲突解决

### 来源间的冲突
**场景**：不同来源对同一问题有不同观点

**处理**：
1. **Tier A vs Tier B**：优先 Tier A
2. **Tier B vs Tier B**：记录争议，询问用户偏好
3. **Tier A/B vs Tier C**：优先 Tier A/B
4. **项目风格 vs 最佳实践**（仅模式 B）：优先项目风格

**示例**：
- Tier A（官方文档）："推荐 A 方案"
- Tier B（专家博客）："我更喜欢 B 方案"
- → 采用 A 方案，但在知识库中注明："部分专家偏好 B 方案"

---

## 实践清单

执行 Stage 5（知识搜索）时使用：

- [ ] 每个来源已标注质量等级（A/B/C/D）
- [ ] Tier D 来源已排除
- [ ] Tier C 来源仅用于线索，未单独作为依据
- [ ] 关键声明有两个独立 Tier A/B 来源支持
- [ ] 证据不足的内容已降级或移入信息缺口
- [ ] 来源 URL 已记录，便于用户验证
- [ ] 冲突的观点已标注并解决
