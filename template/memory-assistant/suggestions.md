# 协作改进建议编写规范

## 写入位置

- 索引文件：`{data_path}/schedule/memory/suggestions/index.md`
- 具体文档：`{data_path}/schedule/memory/suggestions/YYYY-MM-DD-<简短描述>.md`

## 判断标准

从群聊对话中识别用户与 AI 协作的改进机会。满足以下条件时记录：

### 必须记录

- 用户明确提出了对协作方式的改进建议（"下次能不能..."、"我希望你..."）
- 反复出现的协作摩擦点（同一类问题被指出 2 次以上）
- 用户建立了新的工作习惯或流程偏好
- 用户输入不明确导致 Agent 误解（建议用户如何更清晰地表达需求）

### 建议记录

- 发现了可以提效的协作模式（如某类任务可以自动化）
- 用户对 AI 的输出格式、详细程度、回复方式有调整需求
- 跨群聊的共性问题（多个群聊出现类似摩擦）

### 不需要记录

- Agent 自身的技术错误（属于 AI 错误，用 ai_mistake 记录）
- 用户的任务需求本身（属于任务日志）
- 用户的架构/技术决策（属于决策记录）

## 识别信号

- 用户说"下次..."、"以后..."、"能不能..."
- 用户对 AI 的工作流程提出调整
- 同一类交互被反复纠正
- 用户建立了新的约定或偏好
- 用户的表述模糊导致 Agent 理解偏差（如"处理一下"、"优化一下"没有具体标准）

## 建议文档格式

```markdown
---
version: 1.0
created_at: YYYY-MM-DD
updated_at: YYYY-MM-DD
abstract: 一句话说明这个建议针对什么协作问题
---

# 建议标题

## 问题描述

描述当前协作中存在的问题或摩擦点，包括具体场景和频率。

## 改进建议

具体的改进方案，包括：
- AI 应该如何调整行为
- 在什么场景下触发调整
- 预期的改善效果

## 来源

- 来源群聊：<群聊名称>
- 触发事件：<用户说了什么或发生了什么>
```

## index.md 格式

追加一行：

```markdown
| YYYY-MM-DD | 建议标题 | [详情](YYYY-MM-DD-<简短描述>.md) |
```

## 约束

- 聚焦协作方式，不记录技术决策或 AI 错误
- 建议必须可执行，不说"做得更好"这种模糊表述
- 持续追加，不修改历史记录
