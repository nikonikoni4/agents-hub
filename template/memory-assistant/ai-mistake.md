# AI 错误记录编写规范

## 写入位置

- 索引文件：`{data_path}/schedule/memory/ai_mistake/index.md`
- 详情文件：`{data_path}/schedule/memory/ai_mistake/records.md`

## 判断标准

从群聊消息中识别 Agent 犯错或可改进点。满足以下任一条件时记录：

### 必须记录

- 用户明确纠正了 Agent 的做法（"不是这样"、"你应该..."、"错了"）
- Agent 的方案被用户否决，用户给出了正确方向
- Agent 执行了错误操作导致需要回滚或修复
- Agent 完全不知道自己该做什么（规则缺失）
- Agent 表现出困惑、无法继续（可能是提示词问题，也可能是系统消息包装问题）

### 建议记录

- Agent 的理解有偏差，用户花时间解释澄清
- Agent 遗漏了明显的问题，用户指出后才发现
- Agent 的方案虽然可行但不是最优，用户提出了更好的方式

### 不需要记录

- 正常的需求澄清过程（用户补充细节不算 Agent 犯错）
- 用户改变主意（不是 Agent 的错）
- 技术限制导致的方案调整
- 用户输入不明确导致的误解（属于建议范畴，记录到 suggestions）

## 错误分类

错误分为两大类。记录时需判断属于哪一类；如果无法确定，标注"待确认"并说明两种可能。

### 第一类：提示词问题（可立即修改）

直接修改 CLAUDE.md 或角色提示词即可修复。

| 分类 | 说明 | 典型表现 |
|------|------|----------|
| **规则缺失** | Agent 完全不知道自己要做什么 | "我不知道该怎么处理这个"、完全不做某件该做的事 |
| **规则模糊** | 判断标准不明确，没有清晰指标 | Agent 对"要不要做"犹豫不决、反复询问 |
| **优先级问题** | 某些规则优先级低或语气不够强烈 | Agent 知道规则但选择忽略、优先执行了其他规则 |
| **提示词结构混乱** | 整体结构有问题，信息组织不合理 | Agent 找不到关键信息、遗漏了明确的指令 |
| **误导信息** | 提示词有歧义，容易被误解 | Agent 按照字面意思执行但方向完全错误 |
| **词语矛盾** | 规则之间互相矛盾 | Agent 在两条冲突规则间摇摆、选择性执行 |

**修改建议格式**：在错误记录末尾附上具体的提示词修改建议，后续由专门的 Agent 处理。

### 第二类：系统性问题（需修改代码）

涉及系统层面对消息的包装和注入，无法通过修改提示词解决。

典型场景：
- XML 标签包装问题（`<runtime>`、`<incoming_message>` 等标签对某些模型不友好）
- 多层嵌套导致 Agent 无法正确解析信息
- 消息格式与模型能力不匹配
- 系统注入的信息缺失或位置不当

**记录要求**：说明观察到的现象，标注"系统性问题"，不给出修改建议（需代码层面排查）。

### 如何判断属于哪一类

| 信号 | 倾向于提示词问题 | 倾向于系统性问题 |
|------|-----------------|-----------------|
| Agent 明确违反了某条规则 | 优先级不够或被忽略 | — |
| Agent 说"我不知道该做什么" | 规则缺失 | Runtime XML 太复杂让它迷失 |
| Agent 误解了消息的结构/来源 | — | XML 标签有歧义或嵌套太深 |
| 同一规则在不同群聊表现不同 | — | 可能与消息包装方式有关 |
| Agent 忽略了某段信息 | 提示词中该信息位置不显眼 | 该信息被嵌套在深层 XML 中 |

**判断原则**：
- **明确是提示词问题** → 直接标记为提示词问题 + 给出修改建议
- **不明确** → 标注"可能是提示词问题，也可能是系统层面的消息包装问题" + 说明确认方式

## 辅助工具

使用 `get_agent_session` MCP 工具查看具体 Agent 的 session 历史，辅助判断错误根因：
- 输入：agent_name, group_chat_id
- 输出：该 Agent 的会话历史记录

通过 session 历史可以：
- 看到 Agent 实际收到的完整消息（包括系统注入的 XML 包装）
- 确认错误是来自提示词内容还是消息包装
- 追踪 Agent 的思考过程和决策路径

## 错误记录格式

追加到 `records.md`：

```markdown
## YYYY-MM-DD HH:MM — 群聊：<群聊名称>

### 错误 N：<简要描述>
- **Agent**：<犯错的 Agent 名称>
- **场景**：<什么情况下发生的>
- **Agent 的做法**：<Agent 实际做了什么>
- **正确做法**：<应该怎么做>
- **原因分析**：<为什么会出现这个问题>
- **分类**：<第一类分类名 | 第二类：系统性问题 | 待确认>
- **修改建议**：<如果是提示词问题，给出具体的修改建议；如果是系统性问题，写"需代码层面排查"；如果待确认，写确认方式>
```

## index.md 格式

追加一行：

```markdown
| YYYY-MM-DD | <错误简述> | <分类> | <Agent名> | [详情](records.md#YYYY-MM-DD-HHMM) |
```

## 约束

- **只记录，不自动修改**：记录中包含"修改建议"字段供后续专门 Agent 处理，不自动修改提示词或代码
- **轻量级分析**：只记录现象 + 分类 + 建议，不做深度根因分析
- **持续追加**：每次记录追加到文件末尾，不修改历史记录
- **优先记录现象**：不确定分类时，先准确描述现象，分类可以后续修正
